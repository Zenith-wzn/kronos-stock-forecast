# CSI300 Kronos A/B/C 持续排序头实验方案

**状态**：实验前准备方案，尚未启动训练或正式评估  
**生成日期**：2026-08-24  
**目标**：在与既有 Adapter 横截面排序实验一致的 CSI300 数据、输入窗口、预测窗口和评价口径下，比较 Kronos zero-shot、固定排序头和按月持续更新排序头。

## 1. 实验组

| 组别 | Kronos 主干 | 排序头 | 测试期更新 | 目的 |
|---|---|---|---|---|
| A | 冻结 | 无，直接使用 Kronos 原始信号 | 否 | zero-shot 基线 |
| B | 冻结 | 训练期训练一次 | 否 | 测试固定排序头是否有效 |
| C | 冻结 | 与 B 相同的初始排序头 | 按月更新 | 测试持续学习是否有效 |

本轮不持续更新 Adapter，不联合更新 Adapter 与排序头，不做全参数微调。

> B 与 C 的初始权重、结构、输入、损失、训练集和验证集必须完全相同；B/C 唯一差异是测试期是否按月更新。

## 2. 任务和数据口径

- **数据集**：CSI300 日频 OHLCV 数据；使用当前项目固定数据版本，并在报告中注明当前成分股回看历史可能存在幸存者偏差。
- **输入窗口**：与既有 Adapter 实验一致，统一交易日历下过去 **90 个交易日**。
- **预测窗口**：与既有 Adapter 实验一致，未来 **10 个交易日**。
- **主预测信号**：未来 10 日平均预测收盘收益（论文 Eq.13 对齐）。
- **主标签**：未来 10 日平均真实收盘收益：

\[
y_{i,t}=\frac{\operatorname{mean}(P_{i,t+1},\ldots,P_{i,t+10})}{P_{i,t}}-1
\]

- 第 10 日终点收益只能作为辅助口径，不能用于主实验调参或替代 Eq.13 主结果。

沿用既有 Adapter 实验的时间边界，正式运行前按 CSI300 主交易日历复核：

| 隔离期 | 2023-12-18—2023-12-29 | 避免标签重叠 |

## 4. 统一样本清单

运行 A/B/C 前先生成并固定：

```text
eligible_stock_date_pairs.csv
```

每条样本至少记录：

```text
stock, as_of_date, input_start_date, input_end_date,
label_start_date, label_end_date, input_complete,
label_complete, eligible, exclusion_reason
```

主实验严格剔除以下样本：

- 90 日输入窗口存在缺失；
- 未来 10 日标签存在缺失；
- OHLCV 含非有限值；
- 价格小于等于 0；
- 成交量小于 0。

A/B/C 使用完全相同的有效股票—日期交集。

## 5. 排序头

B/C 使用相同的小型排序头和相同输入。排序头可以使用 Kronos 的预测路径摘要及已缓存的 hidden feature，但三组之间的信息集必须保持一致。

推荐采用残差形式：

\[
s^B_{i,t}=z_t(s^K_{i,t})+\alpha g_{\phi}(u_{i,t})
\]

其中：

- \(s^K\)：Kronos 原始 Eq.13 信号；
- \(u\)：Kronos 预测摘要/hidden feature；
- \(z_t\)：同一日期内横截面标准化；
- \(g_\phi\)：排序头；
- \(\alpha\)：仅使用训练/验证集确定。

B/C 排序损失保持一致：Huber 收益损失 + 同一 `as_of_date` 内的 pairwise ranking loss。一个排序 batch 不得混合不同日期的股票。

## 6. C 组按月持续学习流程

采用严格 **test-then-train**：

```text
测试期每个交易日 t：
    1. 使用当前排序头预测 t 日横截面
    2. 保存预测、模型版本和 label_end_date

每个月最后一个测试交易日：
    3. 先完成当天预测
    4. 收集截至当天已成熟的样本
    5. 用成熟样本训练 Challenger 排序头
    6. 通过验证门槛后保存新版本

下个月第一个测试交易日：
    7. Challenger 通过则启用，否则继续使用旧版本
```

标签成熟条件：

\[
\text{label\_end\_date}\leq\text{update\_date}
\]

更新数据固定为：

- 最近 24 个月成熟样本：70%；
- 历史分层 replay：30%；
- 每月更新 1—3 个 epoch；
- Kronos 主干和 tokenizer 始终冻结。

## 7. 指标和统计

主指标：

- 日度 Spearman RankIC 均值；
- RankIC Newey–West `lag=9` t 值；
- moving-block bootstrap 95% CI，block=10。

同时报告：

- Pearson IC；
- RankIC 中位数、标准差和正比例；
- RankICIR；
- Q5-Q1；
- Top50 相对全池超额；
- Top50-Bottom50；
- Top50 赢家命中率；
- 换手率；
- 简化交易成本后的组合表现。

比较增量：

```text
B - A：固定排序头相对 zero-shot 的增益
C - B：持续更新相对固定排序头的增益
C - A：最终持续适配相对 zero-shot 的增益
```

增量必须在共同日期、共同股票交集上做配对统计。

## 8. 成功判据

只有同时满足以下条件，才认为持续排序头有效：

1. C 的测试期主 RankIC 高于 B；
2. C-B 的配对增量方向稳定，不能只由单个月份贡献；
3. 至少 3 个随机种子（建议 100/200/300）提升方向一致；
4. Q5-Q1、Top50 超额或 Top50-Bottom50 没有同步明显恶化；
5. 换手和简化交易成本没有吞噬主要增益。

若 `C > A` 但 `C <= B`，只能说明排序头有效，不能说明持续学习有效。

## 9. 实验前禁止事项

- 测试标签未成熟前训练 C；
- 用测试结果选择学习率、更新频率、replay 比例或损失权重；
- A/B/C 使用不同股票—日期样本；
- 用第 10 日终点收益调参后报告 Eq.13；
- 先更新模型再评估同一更新日；
- 将旧的非严格交易日历结果直接作为唯一公平基线；
- 把 B/C 的监督适配结果称为严格 zero-shot；
- 未经确认直接启动正式 GPU 实验。

## 10. 实施顺序

1. 审计既有 Adapter 实验的窗口、标签和指标实现；
2. 构建统一交易日历和 `eligible_stock_date_pairs.csv`；
3. 运行小规模 smoke test，验证 90/10 窗口和标签成熟逻辑；
4. 在共同样本上生成 A 组严格基线；
5. 训练并冻结 B 组排序头；
6. 以 B 的初始 checkpoint 启动 C 组按月更新；
7. 运行共同样本指标、配对统计和多 seed 汇总；
8. 只有实验方案和 smoke test 获确认后，才启动完整 GPU 运行。
